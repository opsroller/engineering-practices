# License headers and provenance records

Based on the SPDX license list and handling guidance
(https://spdx.org/licenses/, https://spdx.dev/learn/handling-license-info/)
and the REUSE specification 3.3 (https://reuse.software/spec-3.3/).
The project profile's rule always wins; this is the common shape.

## SPDX identifier line

One line near the top of each file, in its comment syntax:

```
// SPDX-License-Identifier: GPL-2.0-or-later
# SPDX-License-Identifier: GPL-2.0-or-later
<!-- SPDX-License-Identifier: CC-BY-4.0 -->
```

With REUSE, add a copyright line too:

```
# SPDX-FileCopyrightText: 2026 Example Project contributors
# SPDX-License-Identifier: GPL-2.0-or-later
```

If the file must start with something else (a shebang, `<?xml`, a
front-matter block, or a required first statement), put the header in
the first comment after it.

## License expressions

| Expression | Means |
|---|---|
| `MIT` | One license |
| `Apache-2.0 OR MIT` | Recipient may choose either |
| `Apache-2.0 AND MIT` | Both apply |
| `GPL-3.0-only WITH Classpath-exception-2.0` | License plus an exception |
| `GPL-2.0-only` / `GPL-2.0-or-later` | GNU licenses always state `-only` or `-or-later` |
| `LicenseRef-<name>` | A license not on the SPDX list (text in `LICENSES/`) |

## Files that cannot hold a comment

Images, audio, fonts, binary data:

- a sidecar `<file>.license` with the two SPDX lines
  (`logo.png.license`), or
- a `REUSE.toml` entry covering a directory:

```toml
version = 1

[[annotations]]
path = "assets/sfx/**"
precedence = "aggregate"
SPDX-FileCopyrightText = "2026 Project contributors"
SPDX-License-Identifier = "CC-BY-4.0"
```

REUSE also expects each used license's text in `LICENSES/<id>.txt`.
The root `LICENSE`/`COPYING` file is exempt from needing a header.
